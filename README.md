## 已确定的产品设计（包括尚未实现的部分）

### 计时与档位

- 档位（tier / 专注档）是核心，启动时只需点击对应计时器，不要求先选任务或标签。
- 当前提供三个可主动记录的档位；最低的碎片化无效时间不提供主动启动按钮。未来希望档位可自定义，睡眠单独处理。
- 各计时器当前使用独立闭包状态，可以各自运行。是否需要限制同时运行，尚未另行确定。
- 标签与档位平行、互不绑定；允许没有标签，标签与备注在计时结束后编辑。

| 当前状态 | 按钮 | 操作与结果 |
| --- | --- | --- |
| `idle` | 开始 | 点击后记录首次开始时间，进入 `running` |
| `running` | 暂停 | 点击后停止累计有效时间，进入 `paused` |
| `paused` | 继续、结束 | 继续回到 `running`；结束保存 Session 并重置为 `idle` |

“已完成”是保存并重置的过渡步骤，当前没有持久的 `ended` 状态。运行中不并排放结束按钮，以减少误触。继续应保留已经累计的时长与首次开始时间。

### 一天的定义与 dayId

最终的“一天”以起床开启、入睡结束，不以午夜分割。

- 起床打卡创建并开启一个 `DayLog`，记录这一天的日期和 `wakeTime`。
- Session 通过 `dayId` 归属这次起床开启的一天。统计先按 `dayId` 选记录，再按档位或标签汇总。
- 例如九月六日起床、九月七日凌晨入睡，期间午夜后的记录仍属于九月六日开启的 DayLog。
- 入睡后应用锁定，起床打卡后解锁。睡眠属于特殊档位。
- 已提出睡眠后一小时内可取消的反悔机制，暂缓实现；不能把取消睡眠直接当作再次起床。
- 统一占位 ID 不足以承担每日分组；当前先保持 `dayId: null` 并临时使用自然日。

实现前仍需确定同一自然日多次开启 DayLog 的编号规则，以及入睡时尚在运行或暂停的计时如何处理。旧记录如何迁移到 DayLog 也需单独讨论，不能直接按自然日自动赋值。

### Session、暂停与合并

Session 指一次计时记录。设计上的起点是首次点击开始，终点是点击结束；当前代码在结束时才创建并保存完整对象。

最终关系为：起止跨度（秒） = `totalTime` + `blankTime`。

- `totalTime` 是真正累计的有效计时时长，不包含暂停。
- `blankTime` 包含中途暂停的空白，也应覆盖最后一次暂停到点击结束之间的空白；精度和取整方式待实现时明确。
- 当前只用定时回调累加 `elapsedSeconds`，尚未实现基于时间戳的校准。现在的 `blankTime: 0` 不代表暂停时间真的为零。
- 以后支持手动添加记录，也支持合并同一天内相邻的 Session；合并不可撤销，需确认提示。合并产生的空白不计入有效专注时长。
- 合并的相邻判定、不同档位能否合并等细节尚未定义，不提前假设。
